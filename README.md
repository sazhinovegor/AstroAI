# AstroVision AI — v0.5 (Research Edition)

Веб-приложение на Streamlit для классификации астрофотографий на **галактики** и **туманности** с помощью EfficientNet-B0.

> Важно: это программный каркас с полным циклом «обучение → инференс → статистика», но не готовая обученная нейросеть. Реальные предсказания появятся только после подготовки размеченного датасета и запуска обучения. Не используйте демонстрационные/непроверенные метрики как научные результаты.

## Что нового в v0.5

**Скорость**
- Mixed precision (AMP): float16 на GPU, bfloat16 на CPU;
- `channels_last`, `pin_memory`, `non_blocking` перенос данных, `cudnn.benchmark`;
- косинусное расписание learning rate с прогревом;
- замер скорости обучения (изображений/сек) и бенчмарк инференса на странице статистики;
- опциональный TTA (test-time augmentation): усреднение предсказаний с отражённым снимком — точнее, чуть медленнее.

**Обучение ИИ**
- запуск обучения прямо из веб-интерфейса (страница «Обучение модели») с живым прогрессом, графиком потерь и логом;
- мягкая остановка после текущей эпохи; ранняя остановка по val_loss;
- двухэтапное дообучение: заморозка backbone на первых эпохах, затем разморозка с малым lr;
- расширенные аугментации (отражения, повороты, кропы, цвет, размытие);
- per-class метрики и история обучения сохраняются в чекпоинте.


**Научная воспроизводимость**
- фиксируемые random seed и версии библиотек/оборудования в отчёте эксперимента;
- проверка точных дубликатов и пересечения `object_id` между train/val/test;
- групповой split по астрономическим объектам через `prepare_dataset.py`;
- независимая test-оценка: macro-F1, balanced accuracy, ROC-AUC, MCC, Brier score, ECE и bootstrap 95% CI;
- CSV с предсказаниями каждого тестового снимка и повторные запуски с разными seed;
- автоматический Markdown-отчёт по фактическим результатам.

## 1. Требования

- Windows 10/11, Python 3.11 или 3.12 (64-bit)
- VS Code
- Интернет для установки библиотек и первоначальной загрузки весов EfficientNet
- Рекомендуется NVIDIA GPU с поддержкой CUDA; при нехватке видеопамяти уменьшите batch size до 8 или 4.
- В этой среде обучения проекта GPU определяется автоматически; если CUDA недоступна, скрипт запустится на CPU.

## 2. Установка в Windows PowerShell

Откройте терминал VS Code в папке `AstroVisionAI`:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Проверьте, видит ли PyTorch видеокарту NVIDIA:

```powershell
python -c "import torch; print('CUDA:', torch.cuda.is_available()); print('GPU:', torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'не обнаружена')"
```

Если выводит `CUDA: False`, установите сборку PyTorch с CUDA для вашей версии драйвера через официальный селектор установки PyTorch (pytorch.org/get-started/locally/), затем повторите проверку. Само наличие NVIDIA-видеокарты ещё не означает, что установлен CUDA-вариант PyTorch.

Если PowerShell запрещает активацию:
```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

## 3. Подготовка датасета

```text
dataset/
  train/
    galaxies/
    nebulae/
  val/
    galaxies/
    nebulae/
  test/
    galaxies/
    nebulae/
```

Поместите изображения JPG/PNG в соответствующие папки:
- `train` — обучение (примерно 70%)
- `val` — подбор модели (примерно 15%)
- `test` — финальная независимая проверка (примерно 15%)

Разделяйте данные **по разным астрономическим объектам**, а не случайно по вариантам одного снимка. Удаляйте дубликаты и проверяйте лицензии. Нельзя помещать разные обработки одного исходного снимка в train и test — это завысит оценку качества. Для первой проверки кода достаточно нескольких десятков изображений каждого класса в train и нескольких в val (это только smoke-test).

## 4. Обучение

**Вариант A — из веб-интерфейса.** Запустите сайт (см. раздел 5), откройте «Обучение модели», проверьте состав датасета, задайте гиперпараметры и нажмите «Запустить обучение». Прогресс, график потерь, скорость (изобр/с) и лог обновляются в реальном времени; обучение можно мягко остановить после текущей эпохи.

**Вариант B — из терминала:**

```powershell
python train.py --data_dir dataset --epochs 15 --batch_size 16 --seed 42
```

Полезные параметры `train.py`:

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `--epochs` | 8 | число эпох |
| `--batch_size` | 16 | при нехватке памяти уменьшите до 8 или 4 |
| `--lr` | 1e-4 | начальный learning rate (голова) |
| `--freeze_epochs` | 2 | сколько первых эпох обучать только классификатор |
| `--patience` | 4 | ранняя остановка: эпох без улучшения val_loss (0 — выкл.) |
| `--img_size` | 224 | размер входа; 160 — быстрее, 256 — точнее |
| `--workers` | 0 | загрузчики данных (0 — безопаснее на Windows) |
| `--no_amp` | — | отключить ускорение mixed precision |
| `--no_aug` | — | отключить расширенные аугментации |
| `--progress_file` | — | JSON-файл живого прогресса (используется сайтом) |
| `--stop_file` | — | флаг мягкой остановки (используется сайтом) |

После обучения появится `models/astrovision_model.pth` (весы, классы, порог, метрики, история).

## 5. Запуск сайта

```powershell
streamlit run app.py
```

- **Анализ снимка** — загрузка JPG/PNG, класс, уверенность, время инференса, опциональный TTA.
- **Обучение модели** — запуск и мониторинг обучения из браузера.
- **Научная статистика** — тестовые метрики, матрица ошибок, per-class метрики, история обучения и бенчмарк скорости инференса.

## 6. Публикация в интернете

1. Создайте приватный или публичный репозиторий GitHub.
2. Загрузите `app.py`, `train.py`, `requirements.txt` и остальные файлы.
3. Не загружайте датасет и тяжёлый файл модели в обычный Git-репозиторий.
4. Подключите репозиторий в Streamlit Community Cloud и укажите `app.py`.
5. Обучение на бесплатном хостинге запускать не рекомендуется (ограничения по памяти и времени): обучайте локально, модель подключайте через безопасное хранилище/релиз. Не храните секреты в коде.

## 7. Ограничения научной интерпретации

- Модель отличает только два заданных класса; это не каталогизация конкретных объектов.
- Значение softmax — оценка модели, не автоматически откалиброванная вероятность истинности.
- Порог «неизвестный объект» — эвристика, её следует подбирать на validation set и проверять на данных вне двух классов.
- Результаты зависят от качества разметки, баланса классов и распределения датасета.
- Для публикации сообщайте состав датасета, правила разделения, метрики по каждому классу и ограничения.


## 8. Научный протокол для конференции

Чтобы результаты можно было проверить, зафиксируйте:
1. Источник и лицензию каждого набора изображений.
2. Число изображений отдельно для каждого класса и каждого раздела.
3. Правило разделения по астрономическим объектам (не по копиям снимков).
4. Версию кода, параметры запуска, устройство и дату эксперимента.
5. Итоговые Accuracy, Precision, Recall и F1-score на независимом test.
6. Матрицу ошибок и несколько примеров верных и ошибочных предсказаний.

Не подбирайте параметры по test: для этого используется validation. Не называйте
оценку softmax подтверждённой вероятностью истинности. Для проверки неизвестных
объектов подготовьте отдельный внешний набор галактик/туманностей вне обучающего
каталога и изображений других типов, а порог подбирайте только на validation.

Архив v0.5 содержит программный код, исследовательские инструкции и шаблоны метаданных, но не содержит обучающих изображений и готовых весов. Поэтому научные метрики появятся только после подготовки реального датасета и фактического запуска обучения.


## 9. Исследовательский рабочий процесс (рекомендуется для ОПТОТЕХ)

1. Соберите `dataset/raw/galaxies` и `dataset/raw/nebulae`. Для каждого файла укажите в `dataset/raw_metadata.csv` класс, устойчивый `object_id`, источник и лицензию. Не используйте один и тот же объект в разных разделах.
2. Создайте разбиение по объектам:

```powershell
python prepare_dataset.py --data_dir dataset
```

3. Проверьте качество данных и происхождение изображений:

```powershell
python audit_dataset.py --data_dir dataset --require_metadata --require_provenance
```

4. Проведите базовый эксперимент на NVIDIA GPU (если не хватает VRAM, уменьшите batch size до 8 или 4):

```powershell
python train.py --data_dir dataset --epochs 20 --batch_size 16 --img_size 224 --seed 42 --require_metadata --require_provenance
```

5. Оцените устойчивость результата к случайной инициализации:

```powershell
python run_experiments.py --data_dir dataset --epochs 20 --batch_size 16 --seeds 42 43 44 --require_metadata --require_provenance
```

6. Создайте отчёт по реальным результатам:

```powershell
python make_research_report.py --metrics models/astrovision_model.metrics.json --experiment models/astrovision_model.experiment.json --audit reports/dataset_audit.json --out research/RESULTS_REPORT.md
```

Скрипт отчёта не придумывает результаты: если модель ещё не обучалась или отчёты отсутствуют, соответствующие данные не появятся.

## 10. Что считается научным результатом

Сам по себе высокий `accuracy` на случайном разбиении изображений не доказывает обобщающую способность. Для защиты важно показать: независимость объектов в test, объём и происхождение выборки, ошибки каждого класса, доверительные интервалы, несколько повторов и ограничения метода. Даже при хороших метриках система является классификатором двух заданных классов, а не средством открытия или подтверждения астрономических объектов.
