# План исследования AstroVision AI

## Тема
Исследование применимости сверточной нейронной сети EfficientNet-B0 для классификации астрономических изображений на два класса: галактики и туманности.

## Цель
Разработать и экспериментально оценить воспроизводимый метод классификации астрофотографий на классы `galaxies` и `nebulae`.

## Исследовательский вопрос
Насколько устойчиво EfficientNet-B0 различает галактики и туманности на независимых изображениях, которые не использовались при обучении и подборе гиперпараметров?

## Гипотеза
Предварительно обученная EfficientNet-B0 после дообучения на размеченных астрофотографиях сможет различать два класса лучше случайного классификатора. Устойчивость результата необходимо подтвердить независимым test-набором и повторными запусками с несколькими seed.

## Данные
Для каждого снимка нужно зафиксировать:
- класс (`galaxies` или `nebulae`);
- источник и URL/идентификатор исходного набора;
- лицензию и условия использования;
- идентификатор астрономического объекта (`object_id`);
- путь к локальному файлу.

В `metadata.csv` используются колонки `path,object_id,source,license`. Значения `path` задаются относительно папки `dataset`, например `train/galaxies/image_001.jpg`.

## Разделение данных
Рекомендуемое начальное соотношение — 70% train, 15% validation, 15% test. Разделение выполняется **по астрономическим объектам**, а не по отдельным фотографиям. Все кадры, варианты обработки и кадрирования одного объекта должны попасть только в один раздел. Test-набор нельзя использовать для выбора эпох, порога, размера изображения или других настроек.

Перед обучением выполнить:

```bash
python audit_dataset.py --data_dir dataset
```

Если есть таблица `metadata.csv`, скрипт дополнительно проверит, не оказался ли один `object_id` в нескольких разделах.

## Метод
1. Использовать EfficientNet-B0 с весами предварительного обучения ImageNet.
2. Заменить последний классификационный слой на два выходных нейрона.
3. На начальном этапе обучать классификатор с замороженной базовой сетью.
4. Разморозить базовую сеть и продолжить fine-tuning с меньшим learning rate.
5. Выбирать лучшую модель по минимальному `validation loss`.
6. Один раз оценить выбранную модель на независимом test-наборе.

## План экспериментов

| Эксперимент | Что меняется | Что фиксируется |
|---|---|---|
| E1 — базовый | Стандартные аугментации, размер 224 | Датасет, split, архитектура, гиперпараметры |
| E2 — без аугментаций | Аугментации отключены | Всё остальное как в E1 |
| E3 — размер 160 | Размер входа 160×160 | Всё остальное как в E1 |
| E4 — размер 256 | Размер входа 256×256 | Всё остальное как в E1 |
| E5 — повторяемость | Три seed: 42, 43, 44 | Один и тот же split и настройки E1 |
| E6 — перенос обучения | Предобученная EfficientNet-B0 против случайной инициализации (`--from_scratch --freeze_epochs 0`) | Одинаковые split, seed, размер, эпохи и бюджет подбора |

Не следует одновременно менять несколько факторов в одном сравнении: иначе нельзя понять, что именно повлияло на результат. Для строгого сравнения каждый вариант повторять с одинаковыми seed.

## Метрики
- Accuracy — доля правильных ответов.
- Balanced Accuracy — средняя полнота по классам; полезна при дисбалансе.
- Precision, Recall и F1 отдельно по каждому классу и macro-average.
- ROC-AUC — способность ранжировать два класса по оценкам модели.
- Matthews Correlation Coefficient (MCC) и Cohen’s kappa — дополнительные меры согласия.
- Confusion matrix — структура ошибок.
- Brier score и Expected Calibration Error — характеристики качества вероятностных оценок.
- 95% bootstrap-интервалы для Accuracy, Balanced Accuracy и macro-F1; при наличии `object_id` используется групповой bootstrap по астрономическим объектам, иначе — по изображениям.

Доверительные интервалы отражают неопределённость из-за конечного размера тестовой выборки. При небольшом test-наборе они будут широкими; нельзя представлять одну точку Accuracy как исчерпывающую характеристику качества.

## Команды

Один обучающий запуск:

```bash
python train.py --data_dir dataset --epochs 15 --batch_size 16 --seed 42
```

Повторные запуски с разными seed:

```bash
python run_experiments.py --data_dir dataset --epochs 15 --batch_size 16 --seeds 42 43 44
```

Контрольный эксперимент без весов ImageNet (обучение с нуля; требует существенно больше данных и вычислений):

```bash
python train.py --data_dir dataset --epochs 30 --batch_size 16 --seed 42 --freeze_epochs 0 --from_scratch --out research_runs/from_scratch/model.pth
```

Сравнение без аугментаций:

```bash
python train.py --data_dir dataset --epochs 15 --batch_size 16 --seed 42 --no_aug --out research_runs/no_aug/model.pth
```

## Дополнение v2.0: сравнительное исследование архитектур

В версии v2.0 основной эксперимент расширен на три backbone: EfficientNet-B0, ResNet50 и ConvNeXt-Tiny. Все архитектуры должны обучаться на одинаковом train/validation/test-разбиении, с одинаковым размером входа, seed, правилами аугментации и сопоставимым бюджетом подбора гиперпараметров. Для каждой архитектуры следует выполнить несколько запусков с разными seed. Сводка строится отдельно для каждой архитектуры; объединять все архитектуры в одну среднюю оценку некорректно.

Команда запуска:

```bash
python run_experiments.py --data_dir dataset --architectures efficientnet_b0 resnet50 convnext_tiny --seeds 42 43 44 --epochs 20 --batch_size 16 --require_metadata --require_provenance
```

При интерпретации результатов учитывайте не только accuracy и macro-F1, но и FAR на независимом OOD-наборе, FRR для целевых снимков, скорость инференса, размер checkpoint и вариативность между seed. Выбор финальной модели делайте только после анализа test/OOD результатов. Не используйте test для подбора архитектуры или порога отказа.
